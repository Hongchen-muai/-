# 圆柱斜轴投影

圆柱投影新增独立“斜轴”入口，支持等角、等面积、任意投影三个现有子模式。正轴、横轴及其他投影保留原来的计算路径。

## 参数与预期

| 参数 | 含义与变化 |
| --- | --- |
| 中心点经度 C | 中央线基点的经度，可精确输入小数。改变它会改变所选地理中心，不覆盖正轴、横轴的中央经线。 |
| 中心点纬度 C | 基点的纬度。改变它会改变中央线经过的地理位置以及圆柱与地球极轴的关系。 |
| 中央线方位角 | 在 C 点从北向顺时针量取。0° 为北向，90° 为东向；经纬度与方位角共同确定中央线大圆。 |
| 轴向标准线角距 | 沿用圆柱的标准线参数。0° 时相切，非零时相割；半径为 R cos φₛ。红蓝线属于轴向坐标，不是地理纬线。 |

默认值为东经 110°、北纬 35°、方位角 60°。中心点 C 的投影坐标始终为 (0, 0)，在三维球面和二维地图中均有标记，三维展开后继续显示对应的 C 点。关闭标准线时一起隐藏该参考标记。

圆柱相切的接触线是一条大圆，不是孤立切点。C 在相切时位于接触大圆上；相割时仍是中央线的基点，但不是球面与圆柱的几何交点。仅提供一个点的经纬度不能唯一确定圆柱轴向，所以需要第三个方位角参数。

调整经纬度时，地图外边框、图上的标准线和 C 的像素位置可能保持不变；需要观察大陆轮廓及地理位置的变化。方位角相差 180° 表示同一条无向中央线。基点纬度为 0°、方位角为 90° 时达到正轴极限；基点纬度为 0°、方位角为 0° 或 180° 时达到横轴极限。极点处的方向采用沿所填中心经线逼近时的局部坐标约定。

## 计算约定

先用 C 点的当地东向 E、北向 N 构造中央线方向 T = sin α E + cos α N，并取新的极轴 K = C × T。对单位球面点 V：

```
λ′ = atan2(V · T, V · C)
φ′ = asin(V · K)
```

将轴向经纬度代入现有圆柱公式得到 (u, v)，再以 β = 90° − α 旋转图面坐标：

```
x = u cos β − v sin β
y = u sin β + v cos β
```

三维球面保持原来的地理极轴方向；圆柱使用逆轴向旋转得到真实的倾斜姿态，展开时逐渐消除面外倾角。两侧共用正反算、地理裁切和变形取样，着色器与 CPU 使用一致的坐标约定。等距性质针对轴向经线；不声称斜轴地图处处地理北向朝上。

参考：[PROJ 通用斜轴变换](https://proj.org/en/stable/operations/projections/ob_tran.html)、[PROJ 斜轴墨卡托的中心点与方位角](https://proj.org/en/stable/operations/projections/omerc.html)。这里仍是球面教学模型，不是椭球 Hotine 生产坐标系统。

## 已验证

- 3 个子模式、81 组参数配置，共 41,938 项检查：独立地理向量基、中心定位、南北半球和极点、标准线、O/P/G/M 连线、展开长度与终点、变形椭圆。
- 正轴/横轴极限与原有模型一致；未启用斜轴时，新增参数不影响原有轴向。
- 独立 PROJ 共 422 个坐标案例通过，包含原有基线、三个斜轴模式的 `ob_tran` 以及球面 `omerc`；最大误差约 2.55e-15 R。`omerc` 对照采用等价的无向方位角主值，完整输入角由向量基与 `ob_tran` 对照覆盖。
- 原有数学与场景回归通过，构建通过。
- 仅做桌面页面验收：精确小数输入、三个模式的映射/展开、南半球连续动画、两侧 C 点、空值恢复、回切原轴向和跨类别保留参数。动画画布非空且持续变化，浏览器无错误。

测试：`node scripts/test-oblique-cylinder.js`、`npm test`；独立 PROJ 对照使用安装了 `pyproj` 的 Python 运行 `scripts/test-proj-oracle.py`。桌面截图见 `artifacts/qa-oblique/`。本次不进行手机适配验收。
